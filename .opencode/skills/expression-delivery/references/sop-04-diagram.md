# SOP 04: Diagram

1. 根据内容特征选择最合适的图表类型，不固定输出全套图。
2. Mermaid、ASCII、PlantUML 或其他 diagram code 均可，按项目和用户要求选择。
3. 图表前先确认节点、边界、方向、读者和粒度。
4. 复杂系统图先用 `reasoning-map` 推演依赖、时序和 RED 点。
5. 验证图表语法、节点命名、边关系和是否服务论证，不堆砌装饰性图表。

## Diagram Type Decision Tree

```text
内容分析
├─ 涉及实体和关系？ -> E-R 图
├─ 涉及模块/组件依赖？ -> 组件图 / architecture diagram
├─ 涉及时间顺序的交互？ -> 时序图
├─ 涉及条件分支和流程？ -> 流程图
├─ 涉及数据处理和传递？ -> DFD 图
├─ 涉及状态转换？ -> 状态图
├─ 涉及用户场景或角色权限？ -> 用例图
├─ 涉及故障/失效分析？ -> FMEA 表格 + 故障树/流程图
├─ 涉及安全/威胁分析？ -> 威胁模型图
├─ 涉及决策/条件判断？ -> 决策树
└─ 涉及项目排期/时间线？ -> 甘特图 / timeline
```

## Relationship Labels

| 关系类型 | 表示 | 含义 | 适用场景 |
| --- | --- | --- | --- |
| 包含 | `-.include.->` | A 包含 B，B 是 A 的一部分 | 用例图 |
| 扩展 | `-.extend.->` | B 扩展 A 的功能 | 用例图 |
| 泛化 | `--|>` | B 继承或泛化自 A | 类图、组件图 |
| 聚合 | `--o` | A 聚合 B，B 可独立存在 | E-R 图、类图 |
| 组合 | `--*` | A 组合 B，B 不能独立存在 | E-R 图、类图 |
| 关联 | `--` 或 `-->` | A 与 B 有关联关系 | E-R 图、类图 |
| 依赖 | `..>` | A 依赖 B，B 变化影响 A | 组件图、类图 |

关系强度通常为：依赖 < 关联 < 聚合 < 组合。

## Grouping Rules

- 节点数 <= 8 时可以不分组。
- 节点数 > 8 时使用 subgraph 按逻辑分组。
- 每个 subgraph 内节点数控制在 3-6 个。
- 分组策略可按层次、模块、流程阶段或职责域选择。
- 数据字典使用 Markdown Table，不强行使用 E-R 图。

## Scenario Bundles

- 新功能开发：用例图、时序图、组件图、必要时甘特图。
- 系统架构设计：组件图、E-R 图、DFD、关键时序图、核心状态图。
- 故障分析：FMEA 表格、故障树/流程图、故障时序图。
- 安全评估：威胁模型图、组件边界图、决策树、防护流程图。
- 项目管理：甘特图、工作流图、交付物关系图。
- 代码重构：重构前/后组件图、重构步骤流程图、风险验证图。

## Anti-overdesign

- 不为简单 CRUD 输出 10+ 个图。
- 不为日志、配置读取等琐碎细节单独画图。
- 不用多种图重复表达同一流程。
- 内容简单时 1-2 个图或不画图。
- 图表数量服务表达目标，不使用固定数量门槛。
