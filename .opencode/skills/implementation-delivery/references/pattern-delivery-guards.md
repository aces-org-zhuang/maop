# Pattern - Delivery Guards

本文件记录旧项目中可迁移的实现交付经验。它是参考模式，不是硬规则。

## 可迁移部分

- 先读设计和现有代码，再实现。
- 将长任务拆成可验证切片。
- 高风险行为优先 TDD 或最小复现。
- 完成声明必须有本轮新鲜验证证据。
- bugfix 需要区分根因、影响范围、修复方案和验收方式。

## 不迁移为硬规则

- 固定每个任务都 commit。
- 固定来源项目目录或实现记录格式。
- 固定 agent/subagent 调用形式。
- 固定仓库外状态变更流程。
- 固定自动化状态机制。

## 使用方式

当项目没有明确实现流程时，可借用该模式组织计划、验证和交付；当项目已有流程时，优先遵循项目流程。
