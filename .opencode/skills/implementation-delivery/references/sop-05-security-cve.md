# SOP 05 - Security CVE

## Goal

处理安全漏洞、CVE、补丁定位或高风险修复时保持证据边界和用户授权。

## Steps

1. 识别 CVE、安全公告、漏洞描述、受影响版本和本地依赖关系。
2. 需要外部证据、专利或安全资料时转入 `research` 或 `patent-fetch`。
3. 验证本地代码或依赖是否受影响，不把公告存在等同于项目受影响。
4. 制定修复、缓解或升级方案，说明兼容性和回归风险。
5. 高成本验证、真实 exploit、破坏性测试或外部系统操作必须获得用户确认。

## Validation

- 安全结论有来源和本地影响判断。
- 不输出可被滥用的攻击细节，除非用户有明确授权且用于防御验证。
