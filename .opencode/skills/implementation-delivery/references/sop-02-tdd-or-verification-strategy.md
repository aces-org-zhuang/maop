# SOP 02 - TDD or Verification Strategy

## Goal

选择合适的测试优先或验证策略，避免只靠直觉实现。

## Steps

1. 判断是否适合 TDD：明确行为、已有测试框架、回归风险高或 bug 可复现时优先 TDD。
2. 若 TDD 成本不合理，选择替代验证：单元测试、集成测试、类型检查、构建、lint、手工流程或最小复现。
3. 对 bugfix，优先写能暴露原始问题的回归测试或最小复现。
4. 对 UI 或平台流程，记录可观察验证步骤。
5. 在实现前明确“什么证据证明完成”。

## Validation

- 验证策略和风险相匹配。
- 没有把“测试不好写”作为完全不验证的理由。
