# SOP 02 - TDD or Verification Strategy

## Goal

选择合适的测试优先或验证策略，避免只靠直觉实现。

## Steps

1. 判断是否适合 TDD：明确行为、已有测试框架、回归风险高或 bug 可复现时优先 TDD。
2. 适合 TDD 时采用 red-green-refactor：先写一个最小失败测试，确认失败原因正确，再写最小实现让测试通过，最后在保持绿色的前提下重构。
3. 没有观察到测试正确失败前，不要把它当作有效回归证据。
4. 若 TDD 成本不合理，选择替代验证：单元测试、集成测试、类型检查、构建、lint、手工流程或最小复现。
5. 对 bugfix，优先写能暴露原始问题的回归测试或最小复现。
6. 对 UI、生成代码、throwaway prototype 或配置变更，可用项目认可的替代验证，但必须说明为什么不采用 TDD。
7. 对 UI 或平台流程，记录可观察验证步骤。
8. 在实现前明确“什么证据证明完成”。

## Validation

- 验证策略和风险相匹配。
- 没有把“测试不好写”作为完全不验证的理由。
- 若选择 TDD，已看到测试先正确失败再通过。
- 若不选择 TDD，已有等价 fresh verification evidence。
