# Requirement Quality Checklist

- [ ] 原始需求和重新表述的需求均可追溯。
- [ ] 用户、场景、目标、约束已分离。
- [ ] 角色、Use Case、功能需求和验收信号已建立映射；没有脱离角色目标的离散功能。
- [ ] 需求没有提前绑定未确认技术方案。
- [ ] 每个关键需求都有可观察验收信号。
- [ ] 开放问题、依赖和范围外内容已列出。
- [ ] 市场、竞品或替代方案只作为范围和差异化依据，不替代用户/Use Case 主轴。
- [ ] 修订项已标注 in-scope、out-of-scope、deferred、rejected 或 assumption 状态。
- [ ] 委派结果未绕过前置门禁；fallback 仅用于兜底，未替代 delegate trigger、上下文隔离、返回契约或 Synthesis Gate。
