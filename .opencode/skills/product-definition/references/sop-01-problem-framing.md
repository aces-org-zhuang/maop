# SOP 01 - Problem Framing

## Goal

把模糊想法转成清晰的问题定义和成功标准，但不提前进入技术设计。

## Steps

1. 区分原始问题、用户提出的解决方案、业务目标和外部约束。
2. 明确目标用户、使用场景、触发条件、当前替代方案和失败成本。
3. 给出 1-3 个可能的问题表述，并标注各自的假设。
4. 识别范围外内容、暂不解决的问题和需要后续研究的证据缺口。
5. 如果存在多个方向，优先推荐最小可验证方向，并说明取舍理由。

## Validation

- 问题表述能回答“谁在什么情况下为什么需要它”。
- 成功标准可观察，不依赖主观满意度。
- 不包含具体技术架构或实现承诺。
