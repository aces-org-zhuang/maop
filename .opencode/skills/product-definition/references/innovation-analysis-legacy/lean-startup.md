# 精益创业 (Lean Startup)

## 概述

精益创业由 Eric Ries 提出，核心是通过快速构建-测量-学习循环，用最小成本验证商业假设，避免开发没人要的产品。

## 核心循环

```
         ┌──────────────┐
         │   BUILD      │ ← 最小可行产品 (MVP)
         │   构建       │
         └──────┬───────┘
                ↓
         ┌──────────────┐
         │   MEASURE    │ ← 收集可衡量数据
         │   测量       │
         └──────┴───────┘
                ↓
         ┌──────────────┐
         │   LEARN      │ ← 从数据中学习
         │   学习       │
         └──────┬───────┘
                ↓
                ↓←────── 验证学习循环
```

## 关键概念

### 1. 最小可行产品 (MVP)

**定义**：能够验证核心假设的最小功能集

**特征**：
- 具备核心价值主张
- 最小功能集合
- 快速发布验证
- 后续迭代基础

**MVP 类型**：
| 类型 | 描述 | 适用场景 |
|------|------|---------|
| 纸质原型 | 未经编码的原型 | 概念验证 |
| 贵宾式 MVP | 人工服务模拟 | 早期市场验证 |
| 单一功能 | 只有一个核心功能 | 最小功能验证 |
| 众筹 MVP | 预售验证需求 | 市场需求验证 |
| 弹弓 MVP | 手动弥补技术不足 | 早期验证 |

### 2. 验证性学习 (Validated Learning)

**核心问题**：我们学到了什么可被验证的认知？

**衡量标准**：
- 可衡量的指标
- 可重复的实验
- 可证明的结果

**示例**：
```
假设：用户愿意为快速配送付费
验证：提供 premium 配送选项，测量转化率
学习：用户确实重视速度，但价格敏感度高于预期
```

### 3. 创新会计 (Innovation Accounting)

**步骤**：
1. **建立基准线** - 当前指标
2. **优化曲线** - 迭代改进指标
3. **切换点** - 决定 pivot 或坚持

**关键指标**：
- 可执行指标 (Executable Metrics)
- 可衡量指标 (Measurable Metrics)
- 可检查指标 (Auditable Metrics)

## 构建-测量-学习实践

### 第一步：识别假设

**价值假设**：
- 用户真的需要这个问题被解决吗？
- 我们的解决方案真的有价值吗？

**增长假设**：
- 用户会如何发现我们的产品？
- 用户会推荐给其他人吗？
- 如何实现规模化？

### 第二步：排优先级

使用 **IMVP 实验优先级**：
1. 高风险高影响 → 最先验证
2. 假设依赖关系 → 按顺序验证
3. 易于验证 → 快速积累学习

### 第三步：设计实验

```
实验设计模板：
- 假设：[具体可测试的假设]
- 成功标准：[可衡量的指标]
- 失败标准：[指标低于阈值]
- 时间范围：[实验周期]
```

### 第四步：分析与决策

| 结果 | 决策 | 行动 |
|------|------|------|
| 假设验证 | 坚持 + 扩展 | 投资放大 |
| 假设证伪 | Pivot | 转向新方向 |
| 不确定 | 迭代实验 | 深入测试 |

## Pivot 与坚持

### Pivot 类型

| 类型 | 描述 | 适用情况 |
|------|------|---------|
| 放大 | 某个功能变核心 | 某个需求超出预期 |
| 缩小 | 核心变功能 | 需要更聚焦 |
| 客户细分 | 服务不同用户 | 核心用户不是预期群体 |
| 客户需求 | 解决不同问题 | 用户有其他更痛的问题 |
| 价值捕获 | 改变盈利模式 | 商业模式有问题 |
| 渠道 | 改变分发渠道 | 用户获取方式不对 |
| 技术 | 改变技术实现 | 有更优技术方案 |

### 何时 Pivot

信号：
- 产品指标停滞不前
- 用户反馈指向不同方向
- 竞争对手超越你
- 市场条件发生变化

### 坚持的信号

- 核心指标持续改善
- 用户参与度提升
- 单位经济模型改善
- 团队信心增强

## 精益画布 vs 商业画布

| 维度 | 精益画布 | 商业画布 |
|------|---------|---------|
| 问题 | Top 3 问题 | 价值主张 |
| 解决方案 | Top 3 功能 | 价值主张 |
| 关键指标 | 成功指标 | 渠道 |
| 独特价值 | 不可复制性 | 收入 |
| 优势 | 屏障/成本 | 成本结构 |

## 实施建议

1. **从一个问题开始** - 不要试图解决所有问题
2. **设定验证期限** - 避免无限验证
3. **建立学习文化** - 失败是学习，不是耻辱
4. **关注可执行指标** -虚荣指标无意义
5. **快速迭代** - 每周至少一次迭代
