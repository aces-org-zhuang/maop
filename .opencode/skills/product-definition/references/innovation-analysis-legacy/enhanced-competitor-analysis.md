# 增强版竞品分析指南

## 概述

本指南在原有竞品研究基础上，提供更深度的分析方法、更全面的分析维度和更实用的分析工具，以实现更加充分和深入的竞品分析。

## 检索来源分类体系

### 来源类别定义

竞品分析必须对所有信息来源进行分类标注，确保可追溯性和可验证性：

| 来源类别 | 标识符 | 典型数据源 | 适用场景 |
|---------|--------|-----------|---------|
| **学术来源** | `academic` | arXiv、Semantic Scholar、OpenAlex、Crossref、学术期刊 | 技术原理验证、研究前沿追踪、理论基础确认 |
| **开源项目** | `open-source` | GitHub、GitLab、开源社区、代码仓库 | 实现方案参考、架构设计学习、工程实践借鉴 |
| **专利来源** | `patent` | USPTO、EPO、Lens、Google Patents、专利数据库 | 技术方案确认、创新保护分析、技术路线规划 |
| **产业现状** | `industry` | 产品官网、技术博客、新闻报道、行业报告、企业文档 | 市场现状确认、产品形态分析、商业实践参考 |

### 来源标注规范

**EvidenceRecord 结构**：
```json
{
  "id": "ev-001",                    // 唯一标识符，用于引用
  "sourceType": "academic|open-source|patent|industry",  // 来源类别
  "sourceName": "来源名称",           // 论文标题/项目名/专利号/网站名
  "sourceUrl": "https://...",        // 原始链接
  "retrievedAt": "2025-01-15",       // 检索日期
  "summary": "证据摘要",             // 关键信息摘要
  "relevance": "关联说明",           // 与本研究的关联
  "categoryLabel": "学术来源|开源项目|专利来源|产业现状"  // 中文标签
}
```

**引用机制**：
- 所有竞品、方案、证据条目通过 `evidenceRefs` 字段引用 `EvidenceRecord.id`
- 报告附录必须包含完整的来源标注表格
- 确保每条结论都能追溯到原始来源

### 各来源类别检索策略

#### 学术来源检索

**推荐工具**：
- arXiv API / Semantic Scholar API / OpenAlex API
- Crossref DOI 元数据查询

**检索要点**：
- 关注技术原理论文而非市场分析文章
- 优先引用高引用量、权威期刊论文
- 记录 DOI、作者、发表年份等关键元数据

#### 开源项目检索

**推荐工具**：
- GitHub GraphQL API / GitHub REST API
- GitHub 搜索（`repo:owner/name` 模式）

**检索要点**：
- 分析代码架构、技术栈、实现方案
- 关注项目活跃度（commit velocity、issue resolution）
- 记录仓库地址、主要贡献者、关键文件路径

#### 专利来源检索

**推荐工具**：
- USPTO ODP API / EPO OPS API
- Lens Patent API（专利-学术跨域联动）
- Google Patents 搜索

**检索要点**：
- 关注技术方案而非商业布局
- 分析专利技术路线和创新保护范围
- 记录专利号、申请日期、权利人、技术分类

#### 产业现状检索

**推荐工具**：
- Tavily Search / Extract API
- 产品官网、技术博客、官方文档
- 行业报告数据库

**检索要点**：
- 确认产品实际形态而非营销叙事
- 关注技术架构文档而非功能宣传
- 记录来源网站、发布日期、关键页面

### 阶段 1：竞品生态系统分析

#### 1.1 竞品全景扫描

**扫描维度**：

**直接竞品扫描**
- 产品类别匹配搜索
- 功能相似度分析
- 目标用户重叠度
- 市场定位对比

**间接竞品扫描**
- 问题解决方案分析
- 用户场景覆盖
- 替代方案识别
- 跨行业竞品

**新兴竞品扫描**
- 初创公司监控
- 融资动态追踪
- 产品发布监控
- 技术趋势分析

**潜在竞品扫描**
- 大公司战略产品
- 平台化威胁
- 生态系统扩展
- 技术整合可能

**扫描工具**：

**搜索引擎优化**
```
搜索策略：
- 产品类别 + "替代品"

- "[用户问题] 解决方案"
- 行业 + "创业公司"
```

**应用商店分析**
```
分析内容：
- 分类排名
- 搜索结果
- 类似应用推荐
- 用户评论关键词
```

**社交媒体监控**

监控平台：
- Twitter/X：产品提及、讨论
- Reddit：社区讨论、推荐
- LinkedIn：公司动态、招聘

```

**融资数据库**

```

│   ├─ 竞品 A

    ├─ 平台 A
    ├─ 平台 B

**图谱分析方法**：

**竞争强度分析**
- 市场份额分布
- 增长率对比
- 用户重叠度
- 功能相似度

- 直接威胁：高市场份额、高增长
- 潜在威胁：创新强、融资多
- 间接威胁：替代方案、平台化
- 生态威胁：大公司进入

**机会空间识别**
- 竞品未覆盖区域
- 竞品薄弱环节
- 市场空白点
- 用户未满足需求

## 深度竞品分析常见错误

### 1. 分析不充分

- 只看表面功能
- 不了解深层逻辑
- 忽视用户反馈
- 缺乏战略分析

### 2. 范围过窄

- 只关注直接竞品
- 忽视间接竞品
- 不考虑潜在威胁
- 缺乏全局视角

### 3. 数据不足

- 数据来源单一
- 数据质量不高
- 数据时效性差
- 数据分析不深

### 4. 洞察不足

- 只报告数据
- 不提取洞察
- 不生成建议
- 不支持决策

### 5. 行动不足

- 只分析不行动
- 不转化为策略
- 不制定计划
- 不跟进执行
