# SOP 02 - User Scenario

## Goal

把问题定义展开为用户场景、边界、流程和异常情况。

## Steps

1. 先定义角色：核心角色、次要角色、系统/运营角色和被明确排除的角色；不要用泛泛“用户”替代角色。
2. 为每个核心角色列出 Use Case：触发条件、前置条件、目标、主成功路径、关键分支和期望结果。
3. 描述主流程和关键分支，必要时转入 `expression-delivery` 生成流程图或用例图。
4. 标注边界：明确做什么、不做什么、以后可能做什么。
5. 记录非功能约束：性能、可靠性、安全、合规、可维护性、可访问性等。
6. 对每个 Use Case 给出可观察的验收信号。

## Validation

- 角色清单明确，且每个核心 Use Case 都绑定到角色、触发条件、目标和验收信号。
- 没有把 UI 细节或技术选型写成业务需求。
- 验收信号能被后续设计和实现阶段引用。
