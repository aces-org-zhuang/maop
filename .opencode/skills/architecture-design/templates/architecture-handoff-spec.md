## 一、组件边界

每个组件必须对应模型中的一个元素,职责与模型 description 一致。

| 组件（FQN） | 显示名 | 归属层 | 职责 | 禁止越界 | 模型依据 | 置信度 |
| --- | --- | --- | --- | --- | --- | --- |
| | | routes / services / domain / ui / external | | | 元素 id | % |

**填写规则**

- 「禁止越界」写该组件**不应承担**的职责,用于实现时防止职责漂移
- 「模型依据」必须填元素 id;写不出则该行置信度不得高于 50%
- 未在模型中出现的组件不得写入本表

## 二、依赖约束

| From | To | 关系 | 类型 | 禁止反向 | 模型依据 |
| --- | --- | --- | --- | --- | --- |
| | | 同步 / 异步 | 强约束 / 弱约束 | 是 / 否 | 关系 id |

**填写规则**

- 方向必须与模型一致:模型 `a -> b` 表示 a 调用 b
- 「禁止反向」为「是」时,实现阶段不得引入反向依赖
- 与外部系统的依赖需标注凭据边界(由谁提供、存放在哪)

## 三、流程锚点

| 流程 | 视图 id | 关键步骤 | 参与组件 | 异常/分支 |
| --- | --- | --- | --- | --- |
| | | | | 轨道二补充 / 无 |

**填写规则**

- 视图 id 必须真实存在于模型中,可被 MCP 的 `read-view` 读取
- 当前 LikeC4 版本不支持条件分支与异常块(见 `03-dynamic-views.md`),这类流程标注「轨道二补充」并给出 Mermaid 位置
- 每条流程锚点应能被实现方用于定位代码改动范围
