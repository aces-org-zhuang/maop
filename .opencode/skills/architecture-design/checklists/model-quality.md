# 模型质量检查清单

交付前逐项确认。任何一项为否时，先修复再交付；无法修复时必须向用户说明残余风险。

## 语言友好

- [ ] 元素显示名、视图标题、描述、关系标签、部署节点名均为中文
- [ ] 标识符（元素 id、视图 id）为英文，未因汉化改动
- [ ] 技术专有名词保留原文（RAGFlow、LLM Wiki、Node.js、HTTP、JSON、API、文件路径、端口）
- [ ] 已用 grep 自检无遗漏英文：

```bash
grep -hoE "(title|description) '[^']*'" src/**/*.c4 | grep -oE "'[^']*'" \
  | grep -E "[A-Za-z]{4,}" | grep -vE "RAGFlow|LLM|Node|HTTP|HTTPS|JSON|API|src/|localhost"
```

  有输出即逐条处理；技术专有名词误报时加入排除列表再确认。

## 图类型路由

- [ ] 已执行 `references/00-diagram-routing.md`，确定目标图类型与轨道
- [ ] 已确认所用 LikeC4 版本（记录在交付说明中）
- [ ] 未用 LikeC4 硬凑类图、状态机图或严格 UML 用例图
- [ ] 未写入当前版本不支持的语法（1.58.0：`opt` `loop` `break` `alt` `try`、视图文件夹分组）
- [ ] 全部图均以 LikeC4 表达，未降级到 Mermaid / PlantUML / 其他工具
- [ ] 使用平替方案的图已向用户说明其代价

## 语法正确性（1.58.0 实测坑位）

- [ ] `shape` 只用了合法值（`rectangle` `component` `storage` `cylinder` `browser` `mobile` `person` `queue` `bucket` `document`），未误用 `database` / `cloud`
- [ ] `color` 只用了合法值，未误用 `teal` / `d2`
- [ ] 关系上未挂 `style { }` 块
- [ ] 部署视图语法正确：使用 `instanceOf`（非 `instance of`）
- [ ] 部署节点类型已在 specification 中用 `deploymentNode` 声明
- [ ] 视图名全局唯一，无 `Duplicate view`

## 模型正确性

- [ ] `likec4 validate` 通过（输出 `✓ Valid`，退出码 0）
- [ ] `likec4 build` 通过（**不可省略**：`dynamic view` 只有 `include` 没有消息时 validate 通过但 build 报 `actors array must not be empty`）
- [ ] `likec4 format --check` 通过（输出 `All N file(s) are formatted`）
- [ ] 嵌套元素跨文件引用使用 FQN（顶层元素用 short name 即可，不应无谓写全名）
- [ ] `include` 未使用通配符（如 `f_*`），1.58.0 不支持
- [ ] 视图属性（title / description / tags / link）写在 predicate 之前
- [ ] 被 `navigateTo` 引用的视图均已具名
- [ ] 模型事实定义在 `model/`，未藏在 `views/`

## 视图质量

- [ ] 视图已具名（导出文件名与 URL 依赖它）
- [ ] `view of <element>` 的作用域被正确利用
- [ ] 元素有意义的 `description`
- [ ] 存在导航入口（`index` 或明确的顶层视图）

## Dynamic View 专项

- [ ] sequence 变体只连接叶子元素
- [ ] `parallel` / `par` 未嵌套（1.58.0 实测禁止）
- [ ] 条件分支/循环/异常已拆成多个 LikeC4 视图，未降级到其他工具
- [ ] 多路径视图的 title 已写清路径条件
- [ ] 步骤元素若不在 model 中，已在视图内 `include`

## 主干优先与视图分离

规则见 `references/11-trunk-first-design.md`。

**主干先行（T1）**

- [ ] 视图先只画主干（happy path / 核心链路），主干经用户确认后才展开分支
- [ ] 主干路径已用一句话说明（触发 → 结果），必经状态明确
- [ ] 分支已登记为清单（编号 / 条件 / 归属层 / 优先级 / 是否本期），而非直接铺进图
- [ ] 未在主干未确认前就开始逐分支画图

**一图一意图（T2）**

- [ ] element view 可见元素 ≤ 12
- [ ] dynamic view 步骤 ≤ 8 或消息 ≤ 10
- [ ] 状态机视图状态数 ≤ 8
- [ ] 信息设计视图关键字段 ≤ 12
- [ ] 超限已拆分，未以「内容完整」为由保留超限视图
- [ ] 主干视图的 `include` 中不含任何仅属于分支的元素（静态视图用 `exclude` 剔除）
- [ ] 分支视图只画增量 + 接缝锚点，未重复主干全部步骤
- [ ] 分支视图 `description` 写明「自 `<主干节点>` 岔出，合流至 `<主干节点>`」
- [ ] 分支视图命名为 `*-branch-<条件>`，与主干视图 `*-main` 成对
- [ ] 外围需求（导出 / 批量 / 兼容旧版）未塞进本期视图

**主干冻结（T3）**

- [ ] 主干确认后未就地修改主干模型或主干视图
- [ ] 分支阶段的改动仅限新增视图与新增关系
- [ ] 发现主干缺陷时已走主干变更门禁并留下裁决记录
- [ ] 主干元素未被删除或重命名，编号未回收

**交付说明**

- [ ] 已说明主干路径、分支清单、视图分工
- [ ] 已核对每张视图的容量
- [ ] 已列出登记但未展开的分支及原因

## 设计推演（走双向推演时）

规则见 `references/10-design-reasoning.md`。

**起点判定**

- [ ] 已判定推演起点
- [ ] **只有 US 是无需上升的起点**；F/NF、I、UI、SRC 任一层起点均已先上升到 US
- [ ] 上升时未跳过途经层（每层有本层特有的遗漏风险）
- [ ] 起点为 UI 时已反向确认「这个界面改动对应哪个业务步骤」
- [ ] 起点为 F/NF 时已确认「新增功能是否对应真实用户诉求，而非技术便利驱动」
- [ ] 需求与实现并行时已做双向交叉

**红绿循环**

- [ ] 每轮三步都执行了：打标 → 选最宽泛的 `🔴` 判断走向 → 取最高保真证据
- [ ] 已输出 `Round N Map` 渐进图，而非最后一次性给结论
- [ ] 只使用 `🔴` / `🟢` 标记，未引入其他状态
- [ ] 每个 `🔴` 都有内联原因或验证动作
- [ ] 关键结论画在图内，未用表格承载
- [ ] 未输出推演过程表、退出检查表、评分表
- [ ] 红点转绿伴随证据变化；无新证据的轮次已识别为空转并调整策略

**覆盖完整性**

- [ ] 每个受影响层的链路完整，无缺失层
- [ ] 每层均已做横向扩展（新增关系 / 新增对外可见行为 / 跨切约束 / 共享状态四类触发条件已检查）
- [ ] 横向分支均已标记：无关的标 `🟢` 并说明理由，未留悬空
- [ ] **横向扩散出的内容未并入主干**，只登记为 `BR-nn` 或标 `🟢` 边界化
- [ ] 路径 B 已回落 US 层确认范围

**诚实性**

- [ ] I 层与 US 层的业务语义未从源码反推，已向用户确认
- [ ] 需求与实现的一致性已交叉验证
- [ ] 发现需求与实现脱节时已标为 `🔴`，未静默跳过

**范围裁决**

- [ ] 底层改动超出原始需求时已停下并交用户裁决，未自行扩大范围

**闭环**

- [ ] 每个 `🔴` 都有：已补齐 / 已边界化 / 有验证动作 / 列为待补证
- [ ] 未停留在「需下钻但没下」的红点状态

## 设计交互与决策树（走七层设计链时）

规则见 `references/08-design-decision-tree.md`。

**流程**

- [ ] 已执行节点 0 规模判定，并告知用户走哪条路径及理由
- [ ] 已先按 `references/11-trunk-first-design.md` 切分主干与分支，再逐层推进
- [ ] 各层均先产出主干并⏸确认，展开分支在主干确认之后
- [ ] 按节点 1-6 逐步推进，未一次性输出全部七层
- [ ] 每个 ⏸ 节点已停下等用户确认
- [ ] 若走局部路径，已说明其余层为何不需要改动
- [ ] US 层已给出 3-5 条候选让用户裁剪，而非让用户从零描述
- [ ] NF 层每项给出可度量推荐值 + 推荐理由

**诚实性**

- [ ] 不可度量的 NF 表述已拒绝写入并给出可度量改写建议
- [ ] AI 未自行拍定 NF 值并当作已确认
- [ ] NF 项已标明结局：已确认 / 待补充 / 不适用
- [ ] SRC 层路径基于真实代码，未凭猜测编造
- [ ] 缺口用「合理推测」填充的情形已避免

**缺口盘点（节点 6，不可省略）**

- [ ] 已输出「待用户确认 / 待补充 / 未覆盖」三类清单
- [ ] 已主动提出 AI 易漏问题（异常路径、数据增长、隐私合规、成功验证指标、运营需要了解的部分）
- [ ] 未因「看起来完整」而跳过盘点

## 七层设计链（需求涉及完整设计链时）

规则见 `references/07-seven-layer-design.md`，落盘骨架见 `templates/seven-layer-chain.md`。

**追溯完整性**

- [ ] 每个 US 的链路完整：US → F/NF → I → UI → SRC
- [ ] 缺失层已明确报告，未静默跳过
- [ ] 关系标签说明了「为什么连接」，不是笼统的「关联」
- [ ] 每个 SRC 单元能回答「服务于哪个 I 步骤或 UI 元素」
- [ ] 超范围实现的 SRC 单元已列为待确认项

**命名规范**

- [ ] 编号格式正确：`US-` `F-` `NF-` `I-` `UI-` `SRC-` + 三位数字
- [ ] 编号全局唯一，删除元素后未回收编号
- [ ] 显示名为中文，编号前缀为英文

**FQN 与多文件**

- [ ] SRC 层的嵌套元素跨文件引用使用 FQN
- [ ] 上五层（US / F / NF / I / UI）未被无谓地强制 FQN，顶层元素用 short name
- [ ] 文件按层拆分，仅 SRC 层继续细分
- [ ] 视图文件按层命名，视图名全局唯一

**视图类型**

- [ ] 各层视图类型与 `references/07-seven-layer-design.md` 第五节对应表一致
- [ ] I 层步骤用 `dynamic view`，状态机用「状态即元素 + 迁移即关系」表达
- [ ] UI 层交互面用 element view，信息设计有表格或清单承载
- [ ] SRC 层时序用 `variant sequence`
- [ ] 构建部署用 `deployment view` 且仅在交付后产出

**各层边界**

- [ ] I 层无源码元素（无类名、函数名、表名、文件名）
- [ ] I 层判据通过：换技术栈该层设计依然成立
- [ ] SRC 层每个单元绑定真实文件路径，无路径者标 `待补充`
- [ ] UI 层同时产出交互设计与信息设计，未只做其一
- [ ] 信息设计覆盖空状态、加载状态、错误状态、无权限状态
- [ ] NF 项均可度量；不可度量者标 `待补充`，未编造指标

**工具路由**

- [ ] 业务状态机用「状态即元素 + 迁移即关系」表达，自反迁移写在 description
- [ ] 类设计用嵌套 + 依赖关系表达；继承关系已在 description 显式记录
- [ ] 泳道用 `stage` 类嵌套容器实现，未写 `swimlane` / `lane` / `participant`
- [ ] 使用平替方案的图已向用户说明代价
- [ ] 构建部署图未产出，或已说明为何此时产出

**必备视图**

- [ ] 存在链路总览、业务设计视角、源码实现视角、功能与非功能框架视图
- [ ] 业务设计视角已排除全部 SRC 元素
- [ ] `dynamic view` 含有显式消息（仅 `include` 会导致 build 布局失败）
