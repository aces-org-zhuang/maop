# 模型质量检查清单

交付前逐项确认。任何一项为否时，先修复再交付；无法修复时必须向用户说明残余风险。

## 语言友好

- [ ] 元素显示名、视图标题、描述、关系标签、部署节点名均为中文
- [ ] 标识符（元素 id、视图 id）为英文，未因汉化改动
- [ ] 技术专有名词保留原文（RAGFlow、LLM Wiki、Node.js、HTTP、JSON、API、文件路径、端口）
- [ ] 已用 grep 自检无遗漏英文：

```bash
grep -hoE "(title|description) '[^']*'" src/**/*.c4 | grep -oE "'[^']*'" \
  | grep -E "[A-Za-z]{4,}" | grep -vE "RAGFlow|LLM|Node|HTTP|HTTPS|JSON|API|src/|localhost"
```

  有输出即逐条处理；技术专有名词误报时加入排除列表再确认。

## 主干优先与视图分离

规则见 `references/11-trunk-first-design.md`。

**主干先行（T1）**

- [ ] 视图先只画主干（happy path / 核心链路），主干经用户确认后才展开分支
- [ ] 主干路径已用一句话说明（触发 → 结果），必经状态明确
- [ ] 分支已登记为清单（编号 / 条件 / 归属环 / 优先级 / 是否本次交付），而非直接铺进图
- [ ] 未在主干未确认前就开始逐分支画图

**一图一意图（T2）**

- [ ] element view 可见元素 ≤ 12
- [ ] dynamic view 步骤 ≤ 8 或消息 ≤ 10
- [ ] 状态机视图状态数 ≤ 8
- [ ] 信息设计视图关键字段 ≤ 12
- [ ] 超限已拆分，未以「内容完整」为由保留超限视图
- [ ] 主干视图的 `include` 中不含任何仅属于分支的元素（静态视图用 `exclude` 剔除）
- [ ] 分支视图只画增量 + 接缝锚点，未重复主干全部步骤
- [ ] 分支视图 `description` 写明「自 `<主干节点>` 岔出，合流至 `<主干节点>`」
- [ ] 分支视图命名为 `*-branch-<条件>`，与主干视图 `*-main` 成对
- [ ] 外围需求（导出 / 批量 / 兼容旧版）未塞进本次交付的视图

**主干冻结（T3）**

- [ ] 主干确认后未就地修改主干模型或主干视图
- [ ] 分支阶段的改动仅限新增视图与新增关系
- [ ] 发现主干缺陷时已走主干变更门禁并留下裁决记录
- [ ] 主干元素未被删除或重命名，编号未回收

**交付说明**

- [ ] 已说明主干路径、分支清单、视图分工
- [ ] 已核对每张视图的容量
- [ ] 已列出登记但未展开的分支及原因

## 设计起点与切分维度

规则见 `references/12-design-origin.md`。

**交付边界**

- [ ] 交付边界已写成一句话，且业务方能说「不是」
- [ ] 边界含可观察结果，不是「优化体验」这类不可验收表述
- [ ] 未确认交付边界就逐环推进
- [ ] 产品愿景未被当作门禁或变更起点

**分叉与收敛**

- [ ] **分叉作为决策执行**：问过「新增什么能力」与「保证什么极端场景」两问
- [ ] **两条链的 US 分别识别**，未把 NF 场景塞进 F 链的 US
- [ ] **收敛已显式说明**：两条链的 SRC 进同一制品与运行时
- [ ] **切分维度已判定**：F 链（业务能力）/ NF 链（极端场景）/ 两条都要
- [ ] 判分叉未用占比（占比无可观察锚点）

**NF 单元是场景，不是角度**

- [ ] **每个 NF 项能答出「谁」**：有明确角色，不是「系统」
- [ ] **每个 NF 项能答出「什么场景」**：具体极端条件，不是常态
- [ ] **每个 NF 项能答出「因此得到什么」**：可感知收益或可判定结果
- [ ] **未用裸角度名当 NF 单元**——「性能」「可用性」「可审计性」单独出现即不合格
- [ ] 切分维度写的是「按极端场景」而非「按质量属性」

**两链关系**

- [ ] **F 与 NF 按同维度处理**，未被建模为「功能 vs 约束」
- [ ] **下钻路径只有一条**：`US → I → UI → SRC`，两条链相同
- [ ] **F / NF 不在路径上**，未画成 `US → F → I` 或 `US → NF → I`
- [ ] **Feature ⊃ US**（超集关系），US 与能力单元清单是并列子集
- [ ] 清单项与 US 的对应边语义正确（`要求` = 清单来源，非路径环节）
- [ ] **清单每项都有对应 US**，无凭空出现的单元
- [ ] F 链的 US 与 NF 链 US 结构同构（有角色、场景、期望、可判定验收）
- [ ] **F 链 US 的验收标准不含任何数值 / 时限 / 比例 / 可用性词**（秒、ms、P95、%、不超过、至少、最多）
- [ ] **F 链的交付边界同样成分纯净**，不含指标值
- [ ] **NF 链的门槛值只出现在自己那条链上**，未渗入 F 链
- [ ] 发现污染时已走成分拆分，指标内容未被静默删除
- [ ] 编号为 `Feature-<序号>-F` 与 `Feature-<序号>-NF`，序号配对
- [ ] **两条链各占一个 model 文件，物理隔离**
- [ ] **一次只推了一条链**，未把另一条链拽进来

**跨链隔离**

- [ ] **无跨链边**（`NF → F 链元素`、`F → NF 链元素` 一律禁止）
- [ ] F 链内未出现任何 NF 元素，NF 链内未出现任何 F 元素
- [ ] 编号段区分：F 链 `I-0xx`/`SRC-0xx`，NF 链 `I-1xx`/`SRC-1xx`
- [ ] 跨链影响是「记录并告知」，未在本链里检视对方链

**全景与目录视图（全量设计时）**

- [ ] **每一环都有全景视图**：F / NF / US / I / UI / SRC 六张
- [ ] SRC 环**有源码文件目录视图**（含真实文件路径与嵌套子单元）
- [ ] SRC 目录视图与 SRC 全景都已产出，两者职责未混淆
- [ ] 全景视图是独立视图，未把其他环的内容塞进链视图
- [ ] 全景视图可跨链 `include`（唯一允许跨链的地方），链视图仍无跨链
- [ ] 增量设计时未产出全景（全景是全量设计的产物）

**跨链接力推演**

- [ ] 链内推演闭环后**已对关联的 F / NF 链起新推演**
- [ ] 关联查询结果已显式给出（不能靠猜）
- [ ] 跨链推演是**重跑红绿循环**，不是在原链里检视
- [ ] **两侧都无法再起新推演**时才停止
- [ ] 「无关联」已显式说明，未留空白

**归属表达**

- [ ] 各环元素嵌套在所属 Feature 之下
- [ ] 视图作用域指向 Feature，打开即见归属容器
