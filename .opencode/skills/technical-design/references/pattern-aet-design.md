# Pattern - AET Design

本文件记录 AET 中可迁移的设计经验。它是参考模式，不是硬规则。

## 可迁移部分

- 先做需求澄清，再做技术设计。
- 设计需要分析现有系统，而不是直接给新架构。
- 用变更边界约束实现范围，避免越界修改。
- 接口、数据、状态和 DFx 策略应在实现前明确。
- 设计产物应能被实现阶段直接消费。

## 不迁移为硬规则

- 固定 RAS/RDS/SDD 名称。
- 固定来源项目目录或记录格式。
- 固定 agent 顺序和 workflow runtime。
- 固定评审分数或回炉次数。

## 使用方式

项目没有既有设计流程时，可参考该模式组合最小足够设计产物；项目已有设计模板时，优先使用项目模板。
