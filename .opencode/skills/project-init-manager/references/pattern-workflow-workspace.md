# Pattern - Workflow Workspace

本文件是可选参考模式，用于项目确实需要长期 AI 协作工作区时。它不是项目初始化默认规则。

## 何时使用

- 团队需要长期保存需求、设计、实现、验证和评审产物。
- 项目已有多个 AI 协作阶段，且需要保存人可读续点上下文。
- 用户明确要求建立研发工作区、feature workspace 或 workflow artifacts。

## 不默认执行

- 不默认创建任何来源项目的私有工作区目录。
- 不默认创建固定的结构化产物、报告、原型或评审目录。
- 不把任何来源系统的自动化状态机制当成静态文件规则。

## 设计原则

1. 优先遵循项目已有目录、docs 规则和协作工具。
2. 若项目没有约定，先定义职责域，再选择目录名。
3. 产物目录应可被 `product-definition`、`technical-design` 和 `implementation-delivery` 消费，但不得要求这些技能绑定固定路径。
4. 仓库外状态和自动化服务状态不应伪装成文件工作区能力。
5. 长期稳定规则进入项目 docs；阶段性记录进入项目约定的 guides 或 workflow workspace。

## 可选职责域

```text
requirements/     产品定义、PRD、验收标准
design/           技术设计、接口、变更边界、验证策略
implementation/   实现计划、变更记录、验证报告
reviews/          需求/设计/代码/交付评审
handoff/          交付摘要、变更说明、待同步材料
state/            人可读续点记录，不替代自动化服务状态
```

## Validation

- 工作区命名来自项目约定或用户确认。
- 新增目录不会覆盖已有文件。
- 目录职责和消费技能已说明。
- 未把某个来源项目的私有约束推广为通用规则。
