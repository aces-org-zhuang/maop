# 设计思维 (Design Thinking)

## 概述

设计思维是一种以人为中心的创新方法论，由 IDEO 和斯坦福 d.school 推广，强调通过深度理解用户需求来创造创新的解决方案。

## 五阶段流程

### 1. 同理心 (Empathize)

**目的**：深入理解用户的需求、感受、动机

**方法**：
- 用户访谈 (1:1 深访)
- 观察法 (现场观察用户行为)
- 民族志研究 (文化背景理解)
- 沉浸式体验 (成为用户)

**输出**：
- 用户画像 (Persona)
- 用户旅程地图 (User Journey Map)
- 同理心地图 (Empathy Map)

### 2. 定义 (Define)

**目的**：综合洞察，明确要解决的核心问题

**方法**：
- 聚类分析 (Affinity Diagram)
- "How Might We" 问题重构
- 故事板 (Storyboarding)
- 5 Why 分析

**输出**：
- 问题陈述 (Point of View)
- 设计挑战定义
- 优先级矩阵

### 3. 创意 (Ideate)

**目的**：生成大量创意解决方案

**方法**：
- 头脑风暴 (Brainstorming)
- SCAMPER (替代、组合、改造、修改、用途、消除、反向)
- 思维导图 (Mind Mapping)
- 随机输入 (Random Input)
- Worst Possible Idea (反向创意)

**原则**：
- 延迟判断
- 激进开放
- 数量优先
- 跨界启发

**输出**：
- 大量创意想法
- 创意分类矩阵
- 候选方案列表

### 4. 原型 (Prototype)

**目的**：用最小成本快速构建解决方案

**方法**：
- 纸质原型
- 角色扮演
- 物理模型
- 数字原型
- 故事板

**原则**：
- 快速 (几个小时到几天)
- 低成本 (可用任何材料)
- 聚焦核心假设

**输出**：
- 可测试的原型
- 实验设计方案

### 5. 测试 (Test)

**目的**：验证原型，获取用户反馈

**方法**：
- 用户测试 (User Testing)
- A/B 测试
-  guerrilla 测试 (街头随机测试)
- 专家评审

**原则**：
- 保持开放心态
- 记录观察和反馈
- 迭代改进

**输出**：
- 用户反馈总结
- 改进建议
- 迭代方向

### 用户旅程地图

- 用户阶段：认知 → 考虑 → 决策 → 使用 → 推荐
- 触点 (Touchpoints)
- 用户行为
- 情绪曲线
- 痛点识别
- 机会点发现

### "How Might We" 问题模板

- How might we... 让用户更容易完成某事
- How might we... 消除某痛点
- How might we... 以更低成本提供某价值
- How might we... 让某流程更愉悦

## 应用场景

| 场景 | 应用重点 |
|------|---------|
| 产品设计 | 用户需求洞察、功能优先级 |
| 服务设计 | 客户旅程、触点优化 |
| 体验优化 | 情感设计、障碍消除 |
| 组织创新 | 文化变革、员工体验 |

## 设计思维 vs 传统开发

| 维度 | 设计思维 | 传统开发 |
|------|---------|---------|
| 起点 | 用户问题 | 技术/业务能力 |
| 过程 | 迭代循环 | 线性阶段 |
| 失败态度 | 欢迎失败 | 避免失败 |
| 成功标准 | 用户价值 | 规格满足 |
| 团队构成 | 跨功能 | 专业分工 |

## 成功要素

1. **高层支持** - 需要资源投入和组织变革
2. **跨功能团队** - 不同背景的协作激发创意
3. **心理安全** - 鼓励尝试、允许失败
4. **快速迭代** - 不追求完美，持续改进
5. **用户参与** - 全程保持用户反馈循环
